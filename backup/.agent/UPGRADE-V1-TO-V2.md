# Upgrading a Project from Agent V1 to V2.0

> This guide is for projects that already have `.agent/` with V1 files from prior sessions.
> If you're starting fresh on a new project, just follow the README quick start — you don't need this.

---

## What you have (V1)

```
your-project/
├── .agent/
│   ├── AGENT.md                        ← V1 protocol
│   ├── PROJECT-CONTEXT.md              ← V1 input (7 sections)
│   ├── phase-1-map.md                  ← V1 structural map
│   ├── phase-2-analysis.md             ← V1 deep analysis
│   ├── phase-3-judgment.md             ← V1 validation decisions
│   ├── recommendations.md              ← V1 task backlog
│   ├── health-scorecard.md             ← V1 health tracking
│   ├── session-log.md                  ← V1 session history
│   ├── session-summary-YYYY-MM-DD.md   ← V1 summaries
│   └── action-log.md                   ← V1 code changes (if any)
```

## What you'll have after (V2.0)

```
your-project/
├── .agent/
│   ├── AGENT.md                        ← REPLACED with V2.0 protocol
│   ├── PROJECT-CONTEXT.md              ← UPDATED with 2 new sections
│   ├── analysis-params.md              ← NEW — generated by agent on first V2 run
│   ├── knowledge-graph.json            ← NEW — built on first V2 run
│   ├── descent.md                      ← NEW — replaces phase-1 + phase-2
│   ├── ascent.md                       ← NEW — roll-ups + transaction trace
│   ├── drift-report.md                 ← NEW — doc vs. code mismatches
│   ├── cross-cut.md                    ← NEW — pattern detection
│   ├── judgment.md                     ← NEW — replaces phase-3-judgment
│   ├── recommendations.md              ← REPLACED with V2 format
│   ├── health-scorecard.md             ← UPDATED format (new columns)
│   ├── session-log.md                  ← KEPT — V2 appends to it
│   ├── session-summary-YYYY-MM-DD.md   ← KEPT — V2 creates new ones
│   ├── action-log.md                   ← KEPT — V2 appends to it
│   └── v1-archive/                     ← YOUR V1 FILES (for reference)
│       ├── AGENT-V1.md
│       ├── phase-1-map.md
│       ├── phase-2-analysis.md
│       └── phase-3-judgment.md
```

## Step-by-step upgrade

### Step 1: Archive V1 analysis files (2 min)

The V1 phase files use a different structure than V2. Keep them for reference but move them out of the agent's path so V2 doesn't try to read them.

```bash
cd your-project/.agent

# Create archive
mkdir -p v1-archive

# Archive the V1 protocol and phase files
cp AGENT.md v1-archive/AGENT-V1.md
mv phase-1-map.md v1-archive/
mv phase-2-analysis.md v1-archive/
mv phase-3-judgment.md v1-archive/

# Keep these — V2 continues using them:
# - session-log.md (V2 appends to it)
# - action-log.md (V2 appends to it)
# - session-summary-*.md (V2 creates new ones alongside old)
# - health-scorecard.md (will be rebuilt with new columns on first V2 run)
# - recommendations.md (will be overwritten on first V2 run)
```

### Step 2: Replace AGENT.md with V2.0 (1 min)

```bash
# From your project root
cp /path/to/recursive-descent-agent/templates/AGENT-TEMPLATE.md .agent/AGENT.md
```

This completely replaces the V1 protocol. The V1 copy is safe in `v1-archive/`.

### Step 3: Update PROJECT-CONTEXT.md (10 min)

V2.0 adds two new sections to PROJECT-CONTEXT.md. You have two options:

**Option A — Add the new sections to your existing file (recommended):**

Open `.agent/PROJECT-CONTEXT.md` and add these two sections. Keep everything else you already filled out.

Add after §4 (Current State), before §5:

```markdown
### 4.5 Revenue context ★ V2.0

- Average transaction value: 
<!-- e.g., "$150 per booking", "$29/mo subscription", "unknown" -->

- Current monthly transactions: 
<!-- e.g., "0 — pre-launch", "~50", "~500" -->

- Revenue model details: 
<!-- e.g., "15% commission on each booking", "$29/mo base + usage" -->

- Biggest revenue risk you're aware of: 
<!-- e.g., "payment flow drops users at confirmation step" -->
```

Add after §5 (Existing Project Docs), before §6:

```markdown
### 5.2 Documentation locations ★ V2.0
<!-- List every document the agent should cross-reference against code for drift. -->

- Project constitution: 
<!-- e.g., "CLAUDE.md" -->

- Architecture docs: 
<!-- e.g., "docs/conventions/ARCHITECTURE.md" -->

- API docs: 
<!-- e.g., "docs/conventions/API.md" -->

- Database docs: 
<!-- e.g., "docs/conventions/DATABASE.md" -->

- Component docs: 
<!-- e.g., "docs/conventions/COMPONENTS.md" -->

- Module docs: 
<!-- e.g., "docs/modules/*.md" -->

- Convention/style docs: 
<!-- e.g., "docs/conventions/CONVENTIONS.md" -->

- Other: 
<!-- any other doc that describes expected code behavior -->
```

Fill both sections out. Be specific — the revenue context powers dollar-value impact scoring, and the documentation list defines what gets checked for drift.

**Option B — Start fresh from the V2 template:**

```bash
cp /path/to/recursive-descent-agent/templates/PROJECT-CONTEXT.md .agent/PROJECT-CONTEXT.md
```

Then re-fill everything. Only do this if your V1 context was minimal or if the product has changed significantly.

### Step 4: Handle the health scorecard (1 min)

The V1 scorecard has fewer columns than V2.0 (no persona scores, no drift count, no analysis mode). You have two options:

**Option A — Let V2 rebuild it (recommended):**

```bash
mv .agent/health-scorecard.md .agent/v1-archive/health-scorecard-v1.md
```

V2 will create a new scorecard on its first run with the full column set. You lose the V1 trend history, but the V1 scores aren't directly comparable to V2 scores anyway (V2 uses persona-weighted scoring).

**Option B — Keep it and let V2 extend it:**

Leave it in place. V2 will attempt to read it during pre-flight, won't find the new columns, and will add them. The V1 history rows will have blanks for persona scores and drift — that's fine, the trend tracking still works for the dimensions that existed in V1.

### Step 5: Run the first V2 session (3–5 hours)

This is a full run — V2 needs to build the knowledge graph from scratch regardless of what V1 already analyzed. The V1 analysis was in a different format that V2 can't parse into its knowledge graph.

```
Read .agent/AGENT.md. This is the first V2.0 run — upgrading from V1.
No knowledge graph exists yet. Execute full protocol:
Phase 0 → Descent → Ascent → Cross-Cut → Judgment → Action → Scorecard.
Build the knowledge graph during descent.
```

After this run completes, you'll have:
- `knowledge-graph.json` — persistent memory built (this is the big win)
- `descent.md` — all V1 maps + analysis replaced with persona-attributed findings
- `drift-report.md` — first drift detection results
- `recommendations.md` — tasks now with business impact scoring
- `health-scorecard.md` — new format with persona scores and drift tracking

### Step 6: Verify the upgrade worked (5 min)

Check these files after the first V2 run:

**`knowledge-graph.json`** — should exist and contain entries for your project files:
```bash
# Quick check: does it exist and have content?
wc -c .agent/knowledge-graph.json
# Should be 50KB–2MB depending on project size

# Quick check: how many files are tracked?
grep -c '"hash"' .agent/knowledge-graph.json
```

**`descent.md`** — should have `[ARCH-NNN]`, `[USER-NNN]`, and `[ADV-NNN]` flags:
```bash
grep -c '\[ARCH-' .agent/descent.md
grep -c '\[USER-' .agent/descent.md
grep -c '\[ADV-' .agent/descent.md
# All three should be non-zero
```

**`drift-report.md`** — should exist if you listed documents in §5.2:
```bash
ls -la .agent/drift-report.md
```

**`recommendations.md`** — tasks should have Business Impact fields:
```bash
grep -c 'Business Impact' .agent/recommendations.md
# Should match the number of tasks
```

**`session-log.md`** — should have a V2 entry appended after V1 entries:
```bash
tail -20 .agent/session-log.md
# Should show the V2 session with knowledge graph stats
```

### Step 7: Subsequent sessions use delta mode (30–60 min)

From now on, your default command is:

```
Read .agent/AGENT.md. Delta run.
Load knowledge-graph.json. Diff against git since last session.
Re-descend into changed files and dependents only.
```

You're upgraded. The knowledge graph handles the rest.

## If something goes wrong

**"V2 agent is confused by V1 files"**
You probably didn't archive the phase files. Check if `phase-1-map.md`, `phase-2-analysis.md`, or `phase-3-judgment.md` still exist in `.agent/`. If so, move them to `v1-archive/`.

**"Knowledge graph wasn't built"**
The first V2 run must be a full cycle, not a delta run. If you told it to do a delta run, there's nothing to delta against. Run the full protocol command from Step 5.

**"Drift report is empty"**
Check that you filled out §5.2 in PROJECT-CONTEXT.md. If no documents are listed, the agent has nothing to check for drift.

**"All three personas are saying the same thing"**
This can happen on the first run as the agent calibrates. Check `analysis-params.md` — the persona weights should differ based on your project stage. If they're all 1.0, the calibration section in AGENT.md may need the project stage to be more specific.

**"I want to go back to V1"**
```bash
cp .agent/v1-archive/AGENT-V1.md .agent/AGENT.md
mv .agent/v1-archive/phase-*.md .agent/
```
Your V1 files are intact in the archive. The V2-generated files (`knowledge-graph.json`, `descent.md`, etc.) won't interfere — V1 doesn't read them.
