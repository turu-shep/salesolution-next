# Guardrails — read before every phase

This repo is mid-pivot and carries a lot of decisions that look like mistakes and aren't. An audit that "fixes" them destroys work. Read this list before touching anything.

## Do not touch

**GATE-signed copy and decisions.** The homepage alignment work has signed gates: the de-numbered framework, the recreated-answers mockup, F-01 = 7 verticals, no live counts. See `docs/handoff/2026-07/09/` and the alignment docs under `docs/strategy/offer-research/alignment/`. If copy looks wrong to you, it may have been argued about already. Propose, don't edit.

**Case-study numbers and names.** `docs/strategy/case-studies/fact-ledger.md` is the source of truth for every number that appears in a case study, and it encodes the "Northern Hydraulics" name collision. Never adjust a case-study figure to match something else you found. If two numbers disagree, that's a finding, not a fix.

**Generated files.** `lib/strategy/niche/briefs.generated.ts` and anything else marked generated is regenerated by its workflow, never hand-edited. Editing it silently reverts on the next run.

**`.engine/`.** Git submodule, pinned by tag. Out of scope entirely. Same for `node_modules/`.

**`seo-project/`.** Legacy, superseded by `.engine` — except `seo-project/data/`, which is the live GSC baseline CSV location. Don't "clean up" either.

**Sanity content.** No publishing. Seed as drafts only. There is still no HTML → Portable Text converter, so don't write one as a side quest.

**Pricing and positioning.** `$30K+` install floor, value-based fee philosophy, the two-door model. Not an audit target.

## Rules that bind every phase

**Next 16 is not the Next.js you know.** Read the relevant guide in `node_modules/next/dist/docs/` before writing routing, caching, metadata, or middleware code. Training data is wrong here, confidently.

**Humanizer on any copy that does change.** Global instruction, non-negotiable, applies to microcopy and error strings too. Facts, numbers, and dates stay verbatim — only the voice changes.

**Term capture.** Any task that writes prose runs `node scripts/glossary-queue.mjs add "term" … --source <type>:<slug>` afterward.

**Voice.** Operator register: terse, declarative, concrete, no hype. Kill-list and owned glossary in `.agents/product-marketing-context.md`. The ICP language rules in `docs/strategy/icp/industrial-distribution.md` list the words that are friction cold — schema, GEO, CTR, ERP/PIM, faceted navigation.

**Dev server hygiene.** `pnpm dev` is pinned to `--webpack` because Next 16 dev is flaky under load. If you hit `jsx-runtime "module factory"` errors or a missing `routes-manifest.json`, it's a stale bundle or an orphaned service worker on localhost:3000, not a code bug. Recover with `pkill -f "next dev"; rm -rf .next; pnpm dev`, then poll for stable 200s before screenshotting. One dev server, one browser.

**Visual checks.** There's no Playwright MCP. Use `npm i --no-save playwright` plus `scripts/_visual-check.mjs` to screenshot and find overflow culprits.

**Secrets.** Real secrets live in the gitignored root file `ss local env`. Never read them into context, never echo them, never paste a value into a doc or a ledger entry. Referring to a variable by name is fine.

## Endpoints that spend real money

Three paths bill per call. Auditing or testing them carelessly turns a review session into an invoice.

- **`/api/probe/ai`** calls Anthropic on every request. Set `PROBE_AI_MOCK=1` for any local work that exercises this path — it returns a canned result and only works when `NODE_ENV !== 'production'` ([lib/probe/ai.ts:35](../../../lib/probe/ai.ts#L35)), so it can't accidentally mask a production problem.
- **`/api/probe`** calls DataForSEO for backlink data. Results cache 24h per apex domain and the spend ledger is only consumed on a cache miss, so **probing many distinct domains is what costs money** — re-probing one domain is free after the first call. Pick one or two fixture domains and reuse them.
- **The DataForSEO MCP** bills the same account. Fine for the handful of Lighthouse runs phase 0 needs. Don't loop it.

Never load-test a live endpoint to prove a rate limit. Read the limiter, write a unit test against it, and reason about the window. If a limit genuinely can't be verified without traffic, say so in the ledger and leave it CONFIRMED-with-uncertainty rather than generating the bill.

## Scope boundaries

**In scope:** `app/`, `components/`, `lib/`, `sanity/` schemas and queries, `scripts/`, config files, `public/` metadata files, docs that describe behavior.

**Out of scope unless a finding points there:** `docs/strategy/**` as a target (it's input, not output), `prompts/**`, `brand/**`, `analysis/**`.

## The honesty rule

If a phase can't complete — a tool fails, a check won't run, a finding can't be reproduced — say so in the ledger and in the session summary. A REFUTED finding is a useful result. A quietly dropped one corrupts the eval and the next session inherits a lie.
